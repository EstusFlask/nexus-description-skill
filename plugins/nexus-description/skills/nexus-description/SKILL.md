# Nexus Description

把 Nexus 模组说明整理成读者能迅速找到下载、安装、操作和重点信息的页面。以实际内容和用户指定的参考风格为依据；配色、语言组合与章节数量随项目调整。

## 明确内容与交付范围

- 找到目标 Mod、当前正文和仓库里的文案源文件；先读适用的维护／发布规则并保留已有改动。已有 BBCode 文件继续作为文案源，避免再建一份会漂移的副本。
- 区分玩家说明、开发资料和历史更新。保留实际依赖、安装路径、操作、兼容限制、署名和 AI 声明；功能以本项目当前事实为准，参考页的功能不是本项目的功能。
- 用户要建议或草稿时交付文案；用户已授权更新指定页面时继续执行，不额外增设确认步骤。页面排版本身不包含新包上传、版本变更、权限／收益调整、仓库公开或向第三方私信。

## 从参考页提取设计

用户给出参考链接时，查看页面内容及实际视觉效果，辨认标题层级、段落长度、列表密度、留白、配色和重点框的用途。只继承适用的设计方法，不复制对方的图片、品牌素材或功能承诺。没有参考时根据原页面的问题直接设计。

先确定读者的阅读顺序，再改格式：

- 标题和一句用途说明建立主题；常用链接放在容易发现的位置。
- 下载选择、依赖、安装和常用操作优先可见，用短列表或顺序步骤组织。
- 同级标题采用一致的字号、颜色和间距。中英文可按章节或条目成组，避免两套长篇说明挤在一起；保留用户要求的语言和阅读习惯。
- 把旧版迁移、完整日志路径等低频细节放入可展开区域。关键安装条件、会影响使用的限制和当前最重要的行动入口保留在展开前。
- 用户要求突出某条信息时，为它安排独立且靠前的视觉层级。招募可用醒目标题、引用底色框和直接联系入口，并写清相关经验、希望附上的作品／账号及后续由谁评估；不因发布招募就授予协作者权限。

写 BBCode 时按需读 [排版与语法示例](references/layout-patterns.md)。示例中的蓝金配色、双语和招募框都是可选模式，不是所有页面的固定模板。

## 生成与核对

在项目既有位置保存正文。可用技能内的结构检查器检查常见标签嵌套：

```text
python <skill-directory>/scripts/check_bbcode.py <description.bbcode>
```

检查器只识别常见标签，不判断布局好坏、页面是否保存或链接是否可访问。另核对原文的实质内容是否遗漏，逐一确认下载和联系链接指向预期对象；保留现有权限，不为修复私有仓库链接擅自更改可见性。

实际更新 Nexus 时再读 [编辑器与公开页验收](references/nexus-editor.md)。使用当前环境提供的合适浏览器／连接工具；缺少可用会话时交付准备好的文件并说明卡点，不把草稿说成已发布。

完成标准：

- **草稿**：文案源完整、结构检查完成，清楚说明尚未更新线上。
- **线上更新**：保存后重新打开或刷新公开页，实际看见重点框、标题、列表和关键链接；验证折叠内容可展开且默认状态合理，检查是否残留原始标签，并保存可展示的截图。
- **仓库同步**：按用户已授权范围提交／推送相关文案和简短维护记录。页面与 Git 的状态分别报告，Git 成功不代表线上已保存。

最终回复给出实际页面或文件、最重要的改动，以及已完成的验证；更新过线上页面时附可查看的截图。
