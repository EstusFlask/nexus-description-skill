# Nexus 编辑器与公开页验收

仅在本次任务包含实际更新 Nexus 时读取。具体按钮名称和页面结构以当前可见界面为准。

## 保存前

确认目标 Mod、已有发布状态与当前正文。保留可恢复的原文，准备好完整替换内容，再进入正文源码模式。只修改任务覆盖的字段；不需要为一次正文排版操作触碰文件上传、权限、收益或版本。

## 富文本编辑器的同步问题

在一次真实 Nexus SCEditor 操作中，填入源码后已经能看到新内容，但页面的 Save 仍为禁用状态：自动填值没有触发外层表单的更改事件。

遇到相同症状，先确认输入确实落在可见的正文源码框，再切回富文本模式核对内容。若 Save 仍未启用，可在该编辑框用真实按键做一次可逆编辑，例如加空格后删除，再切换模式或移出焦点，让编辑器处理输入事件。核对最终文字没有被改坏，再保存。把这个作为症状对应的修复，不要每次都机械操作，也不要因为按钮禁用就改动无关字段来触发保存。

不要依赖历史会话里的元素编号、某一个固定选择器或记忆中的编辑 API。用当前可见页面重新定位控件；通过支持的输入动作编辑，不注入脚本修改框架状态或绕过发布流程。

## 保存后

重新打开或刷新公开页，核对实际正文和目标链接，而不只看编辑器预览或成功提示：

- 顶部重点仍可见，标题层级、颜色和列表符合设计，字号没有意外改变；没有原始 `[color]` 等标签泄漏。
- 必要的安装条件、限制、署名和声明仍保留；下载、源码及联系链接没有串页。
- 折叠控件能展开对应详情，刷新后的默认状态合理。在一次实际页面中，点击整个 spoiler 容器只滚动到了该处，需要点击内部的 Show 控件；用观察到的实际控件处理，别假定整个容器可点击。
- 保存一张能同时看见页面上下文与重点区域的截图；必要时再保存展开详情的截图。按当前工具规范在交付中展示。

一次保存结果不明确时，先只读核查当前公开状态；确认没有保存才重试。一次有针对性的恢复后仍无法确认结果，就保留文案与证据并说明卡点，停止继续写入。不要因没有确认到成功就重复发布公告、改其他字段或试探隐藏接口。

## 维护记录

沿用项目已有的回执／发布记录；没有既有要求时，文案源加简短的结果记录即可。截图和临时预览放在项目适合的位置，不自动把带有账号信息的全屏证据提交仓库。记录正文排版已核对，不把它写成新版本发布、安装包验证或游戏实测。
